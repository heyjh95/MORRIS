# MORIS 웹사이트

한국어·영어로 제공하는 정적 웹사이트입니다. 문구와 이미지는 HTML에서 직접 수정합니다.

## 먼저 수정할 파일

| 바꿀 내용 | 파일 |
| --- | --- |
| 한국어 문구·이미지·링크 | `html/index.html` |
| 영어 문구·이미지·링크 | `html/en.html` |
| 슬라이드·선택 버튼·메뉴 동작 | `js/main.js` |
| 공통 변수·믹스인·타이틀·설명·버튼·아이콘 | `scss/_common.scss` |
| 헤더·히어로·제품·브랜드 등 영역별 스타일 | `scss/layout.scss` |

HTML의 `<!-- 신제품 -->`, `<!-- 제품 카테고리 -->` 같은 주석으로 수정할 영역을 찾습니다. 저장하고 브라우저를 새로고침하면 됩니다.

미정 목적지는 `<a href="#">`로 작성합니다. 실제 섹션 이동과 언어 전환 링크는 해당 주소를 사용합니다.

## CSS 빌드와 확인

Node.js 22 이상을 사용합니다.

```bash
npm ci
npm run build
npm test
```

SCSS를 수정했을 때만 CSS를 다시 빌드합니다. `scss/layout.scss`가 진입점이고, `css/layout.css`와 `css/layout.min.css`를 만듭니다. HTML은 압축 CSS를 읽습니다. CSS 파일을 직접 고치면 다음 빌드에서 덮어씁니다.

웹 서버에서 루트 `index.html`을 열면 한국어 페이지로 이동합니다. HTML 생성 과정은 없습니다.

## 동작과 스타일을 읽는 순서

1. HTML에서 원하는 영역을 찾습니다.
2. `js/main.js`에서 해당 영역의 `init…Slider()`를 읽습니다. 메인·신제품·카테고리·브랜드는 모두 Swiper를 사용합니다.
3. 공통 변수·믹스인·기본 모양은 `scss/_common.scss`, 해당 영역의 차이는 `scss/layout.scss`에서 찾습니다.

실제 사이트의 SCSS는 위 두 파일입니다. `layout.scss`에서 ‘1. 헤더’, ‘2. 히어로’, ‘6. 제품 카테고리’ 등의 주석을 검색하면 해당 영역으로 이동합니다. 모바일 스타일은 각 영역 안의 `@media`에서 함께 수정합니다. 공통 색이나 화면 크기 기준을 바꿀 때는 `_common.scss` 상단의 변수를 수정합니다.

영역 안의 하위 요소는 SCSS 중첩으로 묶습니다. `.main-visual` 안의 `&__image`는 `.main-visual__image`가 됩니다. `&:hover`는 현재 요소에 마우스를 올린 상태이며, `img { ... }`는 현재 요소 안의 이미지에 적용합니다.

비슷한 요소에는 공통 클래스를 함께 붙입니다. `_common.scss`에서 아래 클래스를 고치면 한국어·영어의 해당 요소에 함께 적용됩니다.

| 공통 클래스 | 함께 조절하는 모양 |
| --- | --- |
| `title` | 타이틀의 줄 높이·자간·왼쪽 정렬·줄바꿈 |
| `description` | 설명의 줄 높이·자간·색상·줄바꿈 |
| `button` | 상세·전체 보기 링크의 여백·테두리·둥근 모서리·상태 표시 |
| `circle-button` | 이전·다음 버튼의 원형 모양·크기·정렬·상태 표시 |

예를 들어 `class="description product-categories__description"`은 공통 설명 모양과 카테고리 영역의 설정을 함께 사용합니다. 글자 크기와 굵기는 기존 값을 유지하며 공통 변수로 만들지 않았습니다. 사진 위의 설명과 버튼만 `description--on-dark`, `button--on-dark`로 색상을 구분합니다. 카테고리 선택 버튼과 브랜드 탭의 배치는 각 영역에서 관리합니다.

버튼의 `aria-controls`와 패널의 `id`가 같으면 서로 연결됩니다. 카테고리나 브랜드를 추가할 때는 버튼과 패널을 한 쌍으로 복사하고 고유 ID를 붙입니다. 한국어·영어 페이지에 같은 ID를 사용합니다.

두 언어 페이지와 가로 메뉴·전체 메뉴의 HTML은 각각 직접 관리합니다. 메뉴·섹션을 변경하면 대응하는 부분도 함께 고칩니다. 테스트는 두 메뉴의 일치, 두 언어의 ID·이미지 구성, 버튼과 패널 연결, 파일 경로를 검사합니다. CI는 CSS 빌드 결과도 검사합니다.

자세한 예제는 [현행 코드 해설](study/current-code-guide.md)에 있습니다. 예전 줄별 해설은 [학습 안내](study/README.md)에서 보관본으로 구분합니다.

## 모바일 화면

768px 이하에서는 메인 이미지를 정사각형(1:1) 영역에 `cover`로 꽉 채우며 제목·설명과 함께 넘깁니다. 원본 비율을 유지하며 영역 밖으로 나가는 부분은 잘립니다. 전체는 헤더와 하단 조작 영역을 포함해 최소 `100dvh`를 채우고, 짧은 화면에서는 내용을 읽을 수 있도록 높이가 늘어납니다. 모바일 자동 재생은 끄고 스와이프·이전/다음·선택 버튼을 제공합니다.

신제품 제목·소개·전체 보기 버튼은 한 열로 표시합니다. 고정 팝업은 하단의 ‘스토어·문의’ 버튼으로 접어 두고, 누르면 메뉴를 펼칩니다. 데스크톱의 카드·팝업 배치와 자동 재생은 기존대로 동작합니다.

신제품·제품 카테고리·브랜드 제목은 공통 크기·굵기·왼쪽 여백을 사용합니다. 모바일의 브랜드 메시지는 문구가 콘텐츠 너비를 채우도록 글자 크기를 맞춥니다. 데스크톱의 제품 카테고리는 왼쪽 메뉴와 오른쪽 콘텐츠로 나누고, 콘텐츠 안에서 제목·설명 아래에 이미지 전체를 표시합니다.

화살표는 `images/common/icons.svg`의 공통 SVG를 사용합니다. 아이콘의 크기와 정렬은 `scss/_common.scss`의 `.icon`에서 관리합니다.
